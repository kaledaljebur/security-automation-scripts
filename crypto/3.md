# Linux `passwd` and `shadow` Activity

This activity has been tested in Kali Linux.

This activity introduces two important Linux files related to user accounts and password storage: `/etc/passwd` and `/etc/shadow`. In this activity, you will observe the difference between public account information and protected password hash information. You will also see why Linux separates these two files for security reasons.

## Activity 1: View `/etc/passwd`

In this activity, you will read the `/etc/passwd` file and observe the information stored for each user account. You will notice that this file contains account details such as username, user ID, home directory, and login shell.

```bash
# Read the passwd file
cat /etc/passwd

# Read only the first few lines
head -5 /etc/passwd
```

Notice that each line contains fields separated by `:`.

## Activity 2: Identify the fields

In this activity, you will focus on one user entry and identify the meaning of each field. This helps you understand the structure of `/etc/passwd`.

```bash
# Display the root account entry
grep '^root:' /etc/passwd
```

You can discuss the meaning of the fields:

- username
- password placeholder
- user ID (UID)
- group ID (GID)
- user information / comment field
- home directory
- login shell

## Activity 3: Observe the password placeholder

In this activity, you will check the second field in `/etc/passwd`. You should notice that it usually contains `x` instead of the real password or password hash.

```bash
# Display the root account entry again
grep '^root:' /etc/passwd
```

The `x` means the real password hash is stored in another protected file.

## Activity 4: Try to read `/etc/shadow`

In this activity, you will try to read `/etc/shadow` as a normal user. This helps you observe that Linux protects password hashes using file permissions.

```bash
# Try to read the shadow file
cat /etc/shadow
```

You should normally see a permission denied message unless you are already using elevated privileges.

## Activity 5: Read `/etc/shadow` with `sudo`

In this activity, you will read `/etc/shadow` using `sudo`. You will observe that the file contains password hash information and account password policy data.

```bash
# Read the shadow file with sudo
sudo cat /etc/shadow

# Read only the first few lines
sudo head -5 /etc/shadow
```

## Activity 6: Compare one user in both files

In this activity, you will compare the same user entry in `/etc/passwd` and `/etc/shadow`. This helps you understand how Linux separates general account information from sensitive password data.

```bash
# Show the root entry in passwd
grep '^root:' /etc/passwd

# Show the root entry in shadow
sudo grep '^root:' /etc/shadow
```

Notice:

- `/etc/passwd` is readable
- `/etc/shadow` is protected
- `/etc/passwd` shows `x`
- `/etc/shadow` stores the password hash data

## Example Explanation

Use the following example to understand the fields:

```bash
┌──(kaled㉿kali)-[~]
└─$ grep '^root:' /etc/passwd     
root:x:0:0:root:/root:/usr/bin/zsh
┌──(kaled㉿kali)-[~]
└─$ sudo grep '^root:' /etc/shadow
root:$y$j9T$D2Fkbzjjd4za5ysMQSH4u1$I7Fy3ch4YbUpLLPBZUImsju4ghyJIl8mGdURaUVb5y.:20523:0:99999:7:::

```

From `/etc/passwd`:

- `root` -> the username
- `x` -> a placeholder showing that the real password hash is stored in `/etc/shadow`
- `0` -> the user ID (UID)
- `0` -> the group ID (GID)
- `root` -> the comment or description field
- `/root` -> the home directory
- `/usr/bin/zsh` -> the login shell

From `/etc/shadow`:

- `root` -> the username
- `$y$j9T$D2Fkbzjjd4za5ysMQSH4u1$I7Fy3ch4YbUpLLPBZUImsju4ghyJIl8mGdURaUVb5y.` -> the password hash field
- `20523` -> the last password change date stored as the number of days since January 1, 1970, you may use `date -d "1970-01-01 +20523 days"` to calculate the exact date
- `0` -> the minimum number of days before the password can be changed again
- `99999` -> the maximum number of days the password may be used before it should be changed
- `7` -> the warning period in days before password expiry
- empty field -> the inactivity period after password expiry
- empty field -> the account expiry date
- empty field -> reserved for future use

This example shows that `/etc/passwd` stores general account information, while `/etc/shadow` stores sensitive password hash information and password policy settings.

## Activity 7: Create a new user and inspect the entries

In this activity, you will create a new user account and then check how that user appears in both `/etc/passwd` and `/etc/shadow`. This helps you connect the account creation process with the stored account and password information.

Replace `yourfirstname` with your actual first name before running the commands.

```bash
# Create a new user
sudo adduser yourfirstname

# Add the new user to the sudo group
sudo usermod -aG sudo yourfirstname

# Change the default shell to zsh
sudo chsh -s /bin/zsh yourfirstname

# Copy the zsh configuration file
sudo cp /home/kali/.zshrc /home/yourfirstname/

# Fix ownership of the copied file
sudo chown yourfirstname:yourfirstname /home/yourfirstname/.zshrc

# Check the new user in passwd
grep '^yourfirstname:' /etc/passwd

# Check the new user in shadow
sudo grep '^yourfirstname:' /etc/shadow
```

After running the commands, observe:

- the username in both files
- the home directory of the new user
- the shell assigned to the new user
- the `x` placeholder in `/etc/passwd`
- the password hash entry in `/etc/shadow`

## Activity 8: Check file permissions

In this activity, you will check the permissions of both files. This helps you understand why one file is publicly readable and the other is restricted.

```bash
# Check passwd permissions
ls -l /etc/passwd

# Check shadow permissions
ls -l /etc/shadow
```

Compare the output and observe the permission difference.

## Activity 9: Observe special system accounts

In this activity, you will look for accounts that are not meant for normal interactive login. This helps you understand that not all accounts in `/etc/passwd` are regular user accounts.

```bash
# Search for no-login accounts
grep '/usr/sbin/nologin' /etc/passwd

# Search for false-shell accounts
grep '/bin/false' /etc/passwd
```

- What can happen if an attacker gets a copy of `/etc/shadow`?
