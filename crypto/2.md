This lesson is an introductory practical activity on password hash cracking techniques. The purpose is to help you observe the difference between brute-force attacks, dictionary attacks, and rainbow table attacks using simple examples in Kali Linux. You should run the commands, observe the output, and discuss the meaning of the results during the lesson.

## Brute Force

This activity introduces brute-force cracking. You will see how a tool can try many possible values automatically until it finds the correct one. This helps explain why short and simple passwords are weak.

[Hashcat Source](https://www.kali.org/tools/hashcat/)
```bash
# Move to Desktop if preferred
cd ~/Desktop

# Create sample sha256 and save in hashes.txt
echo -n '123' | openssl dgst -sha256 | awk '{print $2}' | tee hashes.txt

# Read 
cat hashes.txt 

# Crack the hash in hashes.txt file
hashcat -m 1400 -a 3 hashes.txt ?d?d?d
# -m 1400 -> is sha256
# -a 3 -> brute-force / mask
    # -a 0 -> dictionary attack
    # -a 1 -> combinator attack
    # -a 3 -> mask/brute-force attack
    # -a 6 -> dictionary + mask
    # -a 7 -> mask + dictionary
# # ?d -> digit
# three ?d = try all 9-digit numbers
```

## Dictionary attack

This activity introduces dictionary attacks. Instead of trying every possible combination, the attacker tests words and passwords from a prepared list. This helps you understand why common passwords are easy to guess.

```bash
# In the terminal, type the below and answer yes to the question
# Or you can use any other dictionary file 
wordlist

# Check the actual string is should be available in the dictionary
grep -x '123' rockyou.txt

# Back to the Desktop
cd ~/Desktop

# Crack
hashcat -m 1400 -a 0 hashes.txt /usr/share/wordlists/rockyou.txt --show
```

## Rainbow table

This activity introduces rainbow tables. A rainbow table is a table prepared before the attack that contains many possible password values and their related hashes. You will see how these tables can be used to search for matching hashes more quickly. This helps explain why stored passwords should be protected properly and why weak password choices are risky.

[Rainbowcrack Source](https://www.kali.org/tools/rainbowcrack/)
```bash
# Install Rainbow if not available already in Kali 
sudo apt update && sudo apt install rainbowcrack

# Generate the rainbow table
# The table will be /usr/share/rainbowcrack/sha256_numeric#3-3_0_1000x1000_0.rt 
# hence the need for sudo
sudo rtgen sha256 numeric 3 3 0 1000 1000 0
# sha256 -> The hashing algorithm you are targeting
# numeric -> The character set (uses only numbers 0-9)
# 3 3 -> The minimum and maximum password length (exactly 3 characters here)
# 0 -> The Table Index (used to create unique reduction functions)
# 1000 -> The Chain Length (how many passwords are "linked" in one row)
# 1000 -> The Chain Count (how many rows the table will have)
# 0 -> The Part Index (used if you were splitting a massive table into multiple files)

# rtsort need to sort the table generated by rtgen, otherwise rcrack will search the whole table
sudo rtsort .

# Thisn will search and compare with the hashes in rainbow table
sudo rcrack . -l /home/kaled/Desktop/hashes.txt
# You may use rcrack . -h <insert_hash_here>
```
